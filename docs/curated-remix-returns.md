# Curated remix records

The source checkout starts with an empty curated-return collection. It contains no creator submissions, moderation receipts, historical test returns or private review evidence.

A future record must be deliberately prepared for public sharing. A private submission is not a public record, and marking a submission reviewed does not grant publication or reuse rights.

Before adding a record:

1. Confirm permission to publish the selected source, build, public credit and description. Exclude personal accounts, contact information, device/session data and private notes.
2. Check the exact upstream code, asset and runtime terms. Public availability is not permission, and one component's MIT license does not cover all assets.
3. Inspect source and dependencies before any execution. Document reproducible setup, immutable source references and honest limitations. Do not publish test evidence that contains private information.
4. Review the schema and public-field allowlist, use a fresh immutable identifier, and validate the intended public record. Keep moderation data separate.
5. Make an explicit publication decision and review the complete Git diff before merging. No command or review status alone establishes permission.

The legacy Datakin-specific curator helper is a narrow optional workflow, not a general uploader or automatic build/approval system. Do not use it to publish a record unless its component rights, required artifacts and public disclosure scope have been established separately.
